# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

An interview portfolio for a Microsoft Solution Engineer interview ("Interview2 portfolio + Azure and Power BI", per README). There is no build system, package manager, linter, or test suite. The deliverable is one static page, `index.html`, with its styles in `css/`, its scripts in `js/` and its pictures in `images/`.

To preview it, open `index.html` in a browser (`start index.html` from PowerShell). Everything uses classic `<script src>` tags, not ES modules, so it also works from `file://`. Browser automation tools can't open `file://`, so serve the folder over a local HTTP server for those.

## File layout

- `index.html`: the markup, with the stylesheets linked in `<head>` and the scripts at the end of `<body>`.
- `css/`: loaded in this order, which is the cascade order. Later files override earlier ones, so keep the order. `base.css` (export-wrapper base, theme tokens, type, buttons, `.tile`, section bands) → `header.css` → `cover.css` → `hero.css` (hero, crowd, persona, toolkit) → `folders.css` (toolkit glass folders) → `journey.css` (journey band and release dialog) → `sections.css` (habits through footer) → `responsive.css` (the ≤1000 / ≤680 / ≤360px media queries for every section) → `motion.css` (scroll reveal, touch/spotlight, `interpolate-size`, reduced motion).
- `js/`: `core.js` defines `window.Site` (`root`, `motion`, `clamp`, `ease`, `easeInOut`, `lerp`). Every other file is an IIFE that takes `Site` as `S`, so `core.js` must load first. Then `cover.js`, `page.js` (reveal, count-up, header progress, active link, spotlight), `journey.js` (journey scrub and release dialog), `folders.js` (toolkit glass folders), `morph.js` (defines `Site.morph`, used by `crowd.js`, so it must load before it), `crowd.js` (crowd canvas and persona panel), `pulse.js` (persona backdrop), `texteffect.js` (hero heading entrance) and `contact.js` (FAQ buttons, copy email). Feature files don't share state except through the DOM; for example, the persona link opens a release by clicking `.j-item`.

## How the page works

- **Styling** is driven by CSS custom properties on `:root`. The layout is modelled on microsoft.com/windows: a white header with the four-square Microsoft logo, a "Microsoft" wordmark, a divider and "Nora Jin"; a centred hero above the toolkit band (`.screen`, full-bleed via `margin-inline:calc(50% - 50vw)` with matching padding, so its content stays in the page column; `.hero` has `overflow-x:clip` to absorb the scrollbar width). The band has the 21st.dev "Light Mint Cream" gradient plus grain, on `.screen::before` / `::after`, and milk-glass folders.
  - No hard seams: those layers and the persona `.pulse-bg` are masked to fade in over `--feather` at the top. The band is pulled up behind the crowd (`.crowd + .screen`), and the crowd (z 1) fades out at its foot.
  - The bottom `--sink` turns into `#071d4a`, the journey band's start colour; the pulse bars do the same in `js/pulse.js`. `.journey::before` adds a short navy fade over its top edge, so the turning bloom has no hard cut.
  - The band is the hero's last child (`.hero` has no bottom padding). alternating white and `--bg-2` grey bands of flat rounded `.tile` cards; a full-bleed dark `.banner` opening the PathwayIQ section; an AWS → Azure comparison grid; an FAQ accordion; a CTA band; and a multi-column link footer. Fonts are Segoe UI Variable / Cascadia Code, with Figtree / IBM Plex Mono fallbacks from Google Fonts. The toolkit band (fixed mint) and the banner (fixed dark) use fixed colours on purpose, so they look the same in both themes. The footer says it's a personal portfolio and not an official Microsoft page; keep that line. Theming is defined three times in `css/base.css`, and the three must stay in sync:
  1. light tokens on `:root`
  2. dark tokens under `@media (prefers-color-scheme: dark){:root:not([data-theme="light"])…}`
  3. the same dark tokens again under `:root[data-theme="dark"]`

  If you add or change a color, use a token and update all three blocks.
- **Content sections** (anchored by id): `#top` hero → `#path` (release/career layers) → `#habits` (six habits with proof, as a polaroid line) → `#story` (PathwayIQ case study) → `#stack` (AWS-built stack mapped to Azure services) → `#roadmap` ("What ships next") → `#questions` (interview brief as a `<details class="faq">` accordion) → `#contact` (CTA band) → footer.
- **JavaScript** (split across `js/` as above) handles:
  - Cover (`#cover`, before the hero): a pinned intro, a vanilla port of a scroll-scrub video hero.
    - It does not lock the body, and it scrolls freely until the very end. There, a hold (`cEndY`, wheel/touch/key listeners plus a scroll pull-back right after wheel or touch input, only within half a screen) keeps the page at the cover's end while `ccur < .999`, so the hero never scrolls away under a half-faded cover. Links and "Skip intro" are never held, and neither is scrolling up. With `.cover-live`, the section is 500vh taller than the viewport. `cTarget` remaps the raw scroll so the first 440vh play 0–88% (title, habits, final line) and the ending (88–100%: bloom folds, logo, flight to the header) gets the last ~112vh. `ccur` also eases more slowly during the ending (.11, and .07 once past 95.5% for the flight and reveal). `.c-pin` has z-index 3 so the hero's crowd (z 1) and band never show through it, and it sticks under the nav (`--navh` on `<html>`).
    - Eased scroll progress (`ccur` → `--cp`) drives the bloom's rotation, and `--bs` drives its scale. The title blurs out over 0–14%. The six habits play over 20–86%, about 11% each, and `.c-final` comes in over 87–95%.
    - Each of the six petals is one habit. The `.h-lab` labels sit inside `.bloom-stage` at each petal's centre, set by `--x` / `--y` (cos and sin of 45° + 60°·k) × `--hr`. They counter-rotate (a reverse `spin` on `.h-spin` plus `+50deg × --cp`) and counter-scale (`1 / --bs`) so they stay upright and the same size on screen.
    - The active habit `k` gets `.on` on both its petal and its label, and `.c-bloom.focus` dims the other petals. The matching `.c-hab` shows the role and a one-line proof on the dark background, not over the bloom. `cLayout` adds `.c-side` on landscape screens (wider than 680px and width ≥ 1.15 × height). There the bloom slides right by `cshift` px (`--bxs`, eased in over the habits phase), and the text sits on the left with its max width in `--tw`. Portrait screens keep the bloom high and put the text below it. Petal order, label order and `.c-hab` order must match.
    - Each `.h-lab` is an `<a>` that links to its habit card (`#habit-communication` … `#habit-problem-solving`, the ids on the `.trait` articles). Clicking a petal shape clicks its label. `js/polaroids.js` intercepts any click on a `#habit-…` link: it scrolls to `#habits` (`scroll-padding-top` uses `--navh`), brings that print to the middle of the line and rings it (`.pl-flash`), and leaves `#habits` in the URL. A `#habit-…` hash on load does the same. The old `:target` flash only applies without JS.
    - Ending, from 88%:
      - The bloom folds away (`--bo`).
      - The four `.c-sq` Microsoft squares spin out (`--s` per square), then `.c-word` slides out from behind them.
      - From 96%, the logo flies into the header (the flight and the cover's fade take the last 4%) logo (`cfly`, measured in `cLayout` against `.ms-logo svg`). The header logo plays `ms-arrive` when it lands.
      - Header brand: `[.ms-logo: squares + "Microsoft" + divider] [.ms-flower] Nora Jin`. Until the cover logo lands, the nav has `.pre`, which collapses `.ms-logo` to zero width so the flower sits far left. Landing removes `.pre`, and the expanding `.ms-logo` (a max-width transition) slides the flower right to its spot in front of the name. Scrolling back re-adds `.pre`. Without motion, `.pre` is never added. The flight is measured against `.ms-mark`, not the transformed svg.
      - Each `.c-hab` also has an `a.c-go` petal button linking to its habit card, the second way to jump. All six habits share one grid cell, so `cRender` enables `pointer-events` / `tabIndex` only on the visible one.
      - The flight follows a quadratic Bézier arc (`cArc`) that swings up and right before curving into the header. Its progress `f` uses `easeInOut`.
      - A blue star trail (`.c-trail`, 18 `.c-star`s, built in JS and fixed at z-index 29) places each star at an earlier point `f − (i+1)·0.026` on the arc. Stars shrink, fade toward the tail and jitter sideways, then dissolve on landing. Each star twinkles via CSS `twinkle`.
      - The pin's fade to reveal the hero starts only at `f = 0.6`, so the trail crosses the dark sky.
      - `.c-logo` is moved to `<body>` as a fixed layer at z-index 30, so the sticky nav doesn't cover it.
    - Hand-off: `.cover-live` has a negative bottom margin equal to the pin height, so the hero sits directly under the cover's last screen. `cpin.style.opacity` fades to 0 to reveal it. `.cover-live` has no background and no pointer events (only `.c-pin` has them), so the hero is visible and clickable.
    - If `media/cover.mp4` loads, `.has-video` swaps the bloom for the video, scrubbed via `currentTime` with a seek queue. There is no `media/` folder in the repo yet, so today the bloom fallback is what renders. If the video doesn't load, `onerror` removes the `<video>`.
    - The "Skip intro" button scrolls to `#top`. Without `.cover-live`, the cover is one static screen with the title and the final line.
  - Scroll reveal: when motion is allowed, the script adds `.motion` to `<html>` and `.rv` to blocks (the selector list is in the script). An IntersectionObserver adds `.in`, staggering blocks that enter together through `--d`. The hidden state is scoped under `.motion`, so without JS, or with reduced motion, everything shows. Adding `.in` to `.report` also starts the bar and stacked-bar grow animations.
  - Hero text effect (`js/texteffect.js`): a vanilla port of the framer-motion "TextEffect".
    - Elements with `data-te` (`fade` / `blur` / `slide` / `scale`) are split per `data-te-per` (`char` or `word`) into `.te-seg` spans that animate in with a stagger after `data-te-delay`. The `cut` preset ports "VerticalCutReveal": each segment is an overflow-hidden box whose `.te-in` text rises from below with a slight overshoot, and `data-te-stagger` overrides the stagger. The current elements are the eyebrow "Nora Jin" (fade, display size), the h1 (blur, per char) and the motto with its `<small>` (cut, per word, .12s stagger).
    - Letters of a word are wrapped in a no-wrap `.te-word`. The element keeps the full text as its `aria-label`.
    - The gradient `<em>` gets a per-letter slice of its gradient (`--te-w` / `--te-x`, measured), with padding so the g's descender isn't clipped.
    - It plays once, when the hero is in view and the nav has lost `.pre` (the cover's logo has landed). Without motion nothing is split.
  - Count-up on the `.big` numbers in the KPIs and discovery stat (the hero stats row was removed). It parses prefix, number and suffix, then always restores the original text (with a timeout fallback). Keep those numbers in a `prefix + number + suffix` form.
  - Header: scroll progress through `--p` on `.nav::after`, a `.scrolled` shadow, and the active link set by an IntersectionObserver on the sections the nav links point to. The hero `.bloom` still gets `--py` / `--ps` parallax, but it is hidden (`.screen .bloom{display:none}`) since the band went mint.
  - Pointer spotlight on `.tile`: the script sets `--mx` and `--my`, read by `.tile::after`, on hover-capable devices only.
  - Journey (`#path`, `.journey`): a vanilla port of a GSAP ScrollTrigger timeline, with no libraries.
    - `jLayout` sets the section height to the viewport height plus the sideways travel distance (`jdist × 1.15`). `.j-pin` is sticky under the nav (`--navh`).
    - `jScrub` maps scroll progress to `translate3d` on `.j-track`. A front sweeps from 72% to 100% of the viewport width. The axis draws up to it (`--lw`), and each `.j-item` gets `--c` (connector), `--d` (dot) and `--t` / `--t2` (masked text rise) as the front passes. Items alternate `.top` and `.bot` and are positioned by `--i`, `--j0`, `--js` and `--jw`. These are smaller in the ≤680px media query.
    - Pinning only happens with `.j-live`, which is added when motion is allowed. Otherwise the band is a static sideways-scrolling strip. All the CSS variables default to 1, so everything shows.
    - Headless browsers stall `requestAnimationFrame`. To test the scrub there, fire a `resize` event after scrolling.
  - Hero crowd (`#crowd`, between the motto and the toolkit panel): a vanilla canvas port of the Skiper/codepen "crowd" (no GSAP).
    - Busts come from `images/crowd/open-peeps-sheet.png` (Open Peeps, CC0; 15×7 cells of 240×324). Cells 17, 72, 92 and 100 hold a knife and are skipped.
    - The stage is full-bleed (`margin-inline:calc(50% - 50vw)`, like the band), so everyone walks in at the left edge of the screen and out at the right; all busts and balloon people move left to right.
    - Eight `balloon-N.png` people walk a long loop among them. They were cut out of the user's illustration with a scratch script, which isn't in the repo. Each `ASKS[i]` (in `js/crowd.js`, in sprite order) holds the balloon colour `c` and `shape` (`circle` / `square` / `star`), the character `look`, the persona `name` and situation `who`, the question `q`, the project `proj` with its solution steps `how` (an array, rendered as a numbered list), an optional `link` (`ext` URL, or `rel` = index of a journey release to open) and the balloon's position inside the sprite (`bx` / `by`).
    - Clicking a balloon person (rectangle hit test; `getImageData` would be blocked on file://) pauses it, jiggles it, bursts confetti and positions `#ask-card` beside the balloon. The card shows only the question.
    - The same click calls `showPersona(i)`. The toolkit panel (`.hero .screen`) switches to `.persona-on`: the kit and stats are hidden, and `#persona` shows the sprite large with a `.pv-tag` (balloon-shaped `.pv-dot` and `look`), then the name, situation, the question in a `.pv-ask` bubble and a `.pv-solve` card (project, numbered steps, optional link). Everything is tinted with the balloon colour through `--ac`. Browsing between people (‹ ›, or another balloon while the panel is open) dissolves the picture through noise on the `.pv-morph` canvas (`Site.morph`, a vanilla WebGL port of the Morph Gallery shader, adapted to draw transparent sprites contain-fit and bottom-anchored; `fit` 0.78 for the cat must match `.pv-img.cat`), and only `.pv-body` replays its entrance (`.swap`). While a persona is open, `js/pulse.js` fades in a `.pulse-bg` canvas over the hero panel and the bloom fades out. It's the 21st.dev "Pulse Bars / slitted glass" gradient: six bars on a navy backdrop (palette navy 0 → coral .63 → ibis pink .91 → cream 1), on a ramp envelope that falls left to right so the bright bars sit behind the picture and not the text, with shimmering tops (`ph = t·0.17`, amount 0.35). It's drawn per pixel at 48 × 96 and upscaled by CSS for the soft edges. It watches `.persona-on` with a MutationObserver and only animates while that class is on and the panel is on screen. With reduced motion it draws one static frame. The card is mostly clear glass (`.persona`), and `.pv-ask` / `.pv-solve` carry their own navy glass so the text stays readable over the bars. WebGL refuses `file://` images as cross-origin, so opened straight from disk `play()` returns false and the picture just swaps. The morph only shows when the page is served over HTTP (for example GitHub Pages), and it is skipped with reduced motion. ‹ › browse the eight, and "Back to my toolkit" restores the panel.
    - The hidden `.ask-list` buttons (shown on focus) give keyboard and screen-reader access.
    - The animation only runs while the stage is on screen. With reduced motion it draws a static frame.
  - Toolkit glass folders (`.kit`, the three `.kit-col.gf` columns in the hero panel): a vanilla port of the "Glass Folder Cards" component in `js/folders.js` + `css/folders.css`.
    - The HTML holds the content: `.gf-title` (h3), `.gf-meta` (the counts, keep them in step with the sheets) and up to 4 `.gf-sheet`s, each a group of `.chips`. Without JS that is a plain card.
    - The script wraps it in the folder: back panel with generated liquid art (`data-art` picks a recipe in `ART`, `data-seed` an arrangement; painted a few rows per frame), the sheets, a frosted front panel hinged on its bottom edge, and a round key with a chevron.
    - The stage is drawn at 340 × 272 and scaled to the column (max 1.3×); the column's height is set in JS.
    - Rest shows the sheets frosted through the glass, hover leans the glass, click (glass or key) opens it and fans the sheets, and clicking a sheet while open (`data-pick`) lifts it clear so its chips can be read. Escape or a click outside closes it. Closed sheets are `inert`.
    - The first sheet in the HTML sits furthest back and peeks highest, so put the most important group first.
  - Habits polaroid line (`#habits`): a vanilla port of the "Polaroid Line Carousel" component in `js/polaroids.js` + `css/polaroids.css`.
    - The six `.trait` articles stay the content (and the no-JS grid). The script moves them into a caption bar (`.pl-bar`) under a full-bleed `.pl-root`, where only the active one is shown.
    - For each habit it builds a print from the article's `data-photo` (`images/habits/*.jpg`: 640px illustrations, scaled down from the 1254px originals). Those prints get `.pl-photo`: a dark number stamp and no icon badge. A painted landscape (`LAND`) is used only when there is no photo or it fails to load. The note under each print is the habit's name, handwritten.
    - The prints hang from a sagging SVG string. Drag the line, click a print, use ‹ › or ←/→. A spring settles the line, and each print swings with the line's speed and sways at rest. Autoplay steps every 4.5 s while the line is on screen and nobody has touched it.
    - The line's height follows the print width (`CW + 150`). With reduced motion: no swing, no autoplay, jumps snap.
    - It removes `rv` from the articles, since the reveal observer would never see the hidden ones.
  - Company logos live in `images/logos/` (PNGs trimmed of whitespace, plus `volvo.svg` and `symphony3.svg`). The PNGs were converted white-to-alpha, so there are no tiles. They appear as `.j-logos` under each journey title and `.vp-logos` under each dialog title.
    - On the dark journey band they render as white silhouettes (`filter:brightness(0) invert(1)`). In the light dialog they keep their colours, and turn white again in dark mode.
    - `.lg.tall` gives stacked emblem-over-wordmark marks (Dongfeng, Geely) more height.
  - The journey band is a deep-blue gradient with a large turning `.j-bloom`: CSS spin plus `--jp` from scroll. Its light text tokens are scoped to `.j-pin`, not `.journey`, because the release `<dialog>` also lives in the section and must keep the normal surface tokens. Type is scaled site-wide with `html{font-size:106.25%}`. The mapping is v1 Dongfeng, v2 iSoftStone, v3 Volvo / Polestar / Geely, v4.1 Symphony3. v4 (Monash) and Next have none.
  - Release stories: clicking a `.j-item` (`data-i`) opens `<dialog id="ver-dialog">` on the matching `.ver-panel`. The ‹ › buttons and the arrow keys step through releases; Esc, a backdrop click or `#ver-close` closes it. Panel pictures load from `images/v1.jpg`, `v2`, `v3`, `v4`, `v4-1` and `next.jpg`, and the journey card from `images/journey.jpg`, all relative to the HTML file. If a file is missing, `onerror` removes the `<img>` and the `.vp-ph` blue placeholder shows.
  - FAQ: `#faq-open` and `#faq-close` open or close every `details.faq`. Open and close animate in browsers that support `interpolate-size` and `::details-content`.
  - copy-email button: `#copy-email` writes the address to the clipboard and reports in `#copy-out`. If the clipboard fails, it selects the text in `#email-text` instead. The address is hardcoded in the JS, so if it changes, update both the JS and the visible `#email-text`.

## Constraints

- Plain static files with no build step, so it must keep working when opened straight from disk. Don't switch to ES modules, `fetch()` of local files or anything else that `file://` blocks. Google Fonts is the only external resource it loads; outbound `<a href>` links to projects, GitHub and LinkedIn are fine.
- All asset paths (`images/…`, `media/cover.mp4`, `css/…`, `js/…`) are relative to `index.html`.
- The layout must work at phone width with no horizontal scroll.
